Foundations

🏗️

Creating DataFrames Phase 1

A DataFrame is a 2-dimensional labelled table — like a spreadsheet or SQL table — with rows and named columns. It is the core data structure in Pandas.
From a dictionary (most common)
import pandas as pd

df = pd.DataFrame({
    'name':   ['Alice', 'Bob', 'Carol'],
    'dept':   ['IT',    'HR',   'IT'  ],
    'salary': [90000,  75000,  85000 ]
})
From files
df = pd.read_csv('data.csv')
df = pd.read_parquet('data.parquet')   # preferred in DE
df = pd.read_json('data.json')
🎯

Selecting & Indexing Phase 1

.loc[] selects by label (column name, index label). .iloc[] selects by integer position (0-based). Use df['col'] for a single column Series, df[['a','b']] for multiple columns as a DataFrame.
MethodBased onExample

df.loc[0:2, ['name', 'salary']]

# first 3 rows, first 2 columns (by position)
df.iloc[:3, :2]
🔍

Filtering & Sorting Phase 1

Boolean filtering passes a True/False mask over rows. Combine conditions with & (AND), | (OR), ~ (NOT) — always wrap each condition in parentheses.
# single condition
df[df['salary'] > 80000]

# AND — both must be true
df[(df['dept'] == 'IT') & (df['salary'] > 85000)]

# OR — either is true
df[(df['dept'] == 'IT') | (df['dept'] == 'Finance')]

# isin() — match against a list
df[df['dept'].isin(['IT', 'Finance'])]

# sort descending
df.sort_values(['dept', 'salary'], ascending=[True, False])
✂️

Rename & Drop Phase 1

rename() changes column/index names without altering data. drop() removes rows or columns. inplace=True modifies the df directly instead of returning a copy.
# rename one or more columns
df.rename(columns={'salary': 'emp_salary'}, inplace=True)

# drop columns
df.drop(columns=['bonus', '_tmp'], inplace=True)

# drop specific rows by index label
df.drop(index=[0, 3], inplace=True)

# always reset index after dropping rows
df.reset_index(drop=True, inplace=True)

Cleaning & Preparation

🧹

Null Handling Phase 2

NaN (Not a Number) is Pandas' placeholder for missing data. isnull() detects them, dropna() removes rows with them, fillna() replaces them with a value or strategy like mean/forward-fill.
# how many nulls per column?
df.isnull().sum()

# drop rows if ANY column is null
df.dropna()

# drop only when a specific column is null
df.dropna(subset=['salary'])

# fill with column mean (numeric)
df['salary'] = df['salary'].fillna(df['salary'].mean())

# fill with static value
df['dept'] = df['dept'].fillna('Unknown')

# forward-fill: copy previous row's value
df['sales'] = df['sales'].ffill()

# backward-fill: copy next row's value
df['sales'] = df['sales'].bfill()
🔧

Types, Duplicates & Replace Phase 2

astype() casts a column to a new dtype — important for memory and correctness. drop_duplicates() keeps only the first occurrence of repeated rows. replace() swaps specific values.
# cast column types
df['salary'] = df['salary'].astype('float64')
df['id']     = df['id'].astype('int32')     # halves memory

# count and remove duplicates
df.duplicated().sum()
df.drop_duplicates()
df.drop_duplicates(subset=['email'])         # unique per email

# replace values (like a lookup swap)
df['dept'] = df['dept'].replace({
    'IT': 'Technology', 'HR': 'People'
})
📝

String Operations Phase 2

The .str accessor lets you apply string methods to an entire column at once — vectorised, no loops needed. Works on columns with object or string dtype.
df['name'].str.lower()                # 'Alice' → 'alice'
df['name'].str.upper()                # 'alice' → 'ALICE'
df['name'].str.strip()                # remove leading/trailing spaces
df['email'].str.contains('@gmail')   # True/False mask
df['dept'].str.replace('IT', 'Tech')  # find & replace
df['full_name'].str.split(' ', expand=True) # split to cols
df['code'].str.startswith('EMP')     # True/False
df['desc'].str.len()                  # character count
df['name'].str.extract(r'(\d+)')     # regex capture

Aggregations & Analysis

📊

groupby + agg Phase 3

groupby() splits the DataFrame into groups based on a column's values — like SQL GROUP BY. agg() then applies one or more aggregation functions (sum, mean, count, max…) to each group.
# single aggregation
df.groupby('dept')['salary'].mean()

# multiple metrics in one call (named aggregation)
df.groupby('dept').agg(
    avg_sal   = ('salary', 'mean'),
    max_sal   = ('salary', 'max'),
    headcount = ('name',   'count'),
    total_sal = ('salary', 'sum')
)

# frequency count of a column
df['dept'].value_counts(normalize=True)  # as %
⚡

transform — group metric on each row Phase 3

transform() computes a group-level statistic but returns a Series the same length as the original DataFrame — so you can add the group result as a new column without losing any rows. Unlike agg() which collapses rows.
# add department average back to every row
df['dept_avg'] = (
    df.groupby('dept')['salary']
      .transform('mean')
)

# now flag above-average employees
df['above_avg'] = df['salary'] > df['dept_avg']

# % of dept total  (transform + divide)
df['pct_of_dept'] = (
    df['salary'] / df.groupby('dept')['salary'].transform('sum')
)

Used heavily in PySpark, dbt, analytics engineering, and ML feature engineering.

Joins & Merges

🔗

merge / concat / join Phase 4

merge() combines two DataFrames on a key column — directly equivalent to SQL JOINs. concat() stacks DataFrames vertically (rows) or horizontally (columns). join() is a shortcut for merging on the index.
how=KeepsSQL equivalent
innerOnly rows that match in both tablesINNER JOIN
leftAll left rows + matching right (NaN if no match)LEFT JOIN
rightAll right rows + matching left (NaN if no match)RIGHT JOIN
outerAll rows from both, NaN where no matchFULL OUTER JOIN
# basic merge on one key
pd.merge(orders, customers, on='customer_id', how='left')

# composite key (multiple columns)
pd.merge(df1, df2, on=['dept', 'year'], how='inner')

# different column names in each table
pd.merge(df1, df2, left_on='id', right_on='emp_id', how='inner')

# stack rows (UNION ALL equivalent)
pd.concat([jan_df, feb_df, mar_df], ignore_index=True)

# stack columns side-by-side
pd.concat([df_features, df_labels], axis=1)

Functions & Transformations

🛠️

map vs apply vs transform Phase 5

Three ways to apply custom logic — they differ in what they operate on and what shape they return. Choosing the right one matters for readability, performance, and correctness.

map()

Element-wise on a single Series. Best for dictionary lookups or simple 1-to-1 replacements. Fastest of the three for this use case.
# dict lookup
df['dept'].map({
  'IT': 'Technology',
  'HR': 'People'
})

# lambda
df['salary'].map(
  lambda x: x / 1000
)

apply()

Custom function on a Series or full DataFrame rows/cols. Most flexible but slowest. Use when vectorised alternatives don't exist.
# on a column
df['salary'].apply(
  lambda x: x * 1.1
)

# across rows (axis=1)
df.apply(
  lambda r: r['a'] + r['b'],
  axis=1
)

transform()

After groupby — returns same shape as original. Adds a group-level metric back to every individual row without collapsing the DataFrame.
# dept mean on every row
df.groupby('dept')
  ['salary']
  .transform('mean')

# group rank
df.groupby('dept')
  ['salary']
  .transform('rank')

⚡ Always prefer vectorised operations (df['salary'] * 1.1) over apply(lambda…) — 10–100× faster. Use np.where() for conditionals instead of row-wise apply.

Reshaping

🔄

pivot_table Phase 6

pivot_table() reshapes data so that unique values of one column become column headers — turning a long table into a summary matrix. Think of it as GROUP BY + CASE WHEN in SQL.
# dept × year salary matrix
df.pivot_table(
    values     = 'salary',
    index      = 'dept',    # rows
    columns    = 'year',    # new columns
    aggfunc    = 'mean',
    fill_value = 0
)
# result: rows=dept, cols=each year, values=avg salary
↔️

melt — wide → long Phase 6

melt() is the inverse of pivot — it takes multiple value columns and collapses them into two columns: a variable column (the old header) and a value column. Converts "wide" format to "long" (normalised) format.
# BEFORE: Q1  Q2  Q3  Q4 are separate columns
# AFTER:  quarter | sales  (two columns, more rows)

df.melt(
    id_vars    = ['name', 'dept'],
    value_vars = ['Q1', 'Q2', 'Q3', 'Q4'],
    var_name   = 'quarter',
    value_name = 'sales'
)

Essential for ML preprocessing, normalised analytics tables, and visualisation libraries.

Method Chaining & Multi-Index

⛓️

Method Chaining Phase 7

Instead of re-assigning df after every step, chain method calls together in one expression. Each method returns a DataFrame, so the next method operates on it immediately. Produces readable, pipeline-style code.
❌ Repetitive re-assignment
df = df.dropna()
df = df.sort_values('salary')
df = df.rename(columns={'salary':'emp_salary'})
df = df[df['emp_salary'] > 80000]
✅ Clean method chain
result = (
    df
    .dropna()
    .sort_values('salary')
    .rename(columns={'salary': 'emp_salary'})
    .query('emp_salary > 80000')
    .assign(bonus=lambda x: x['emp_salary'] * 0.1)
    .reset_index(drop=True)
)

Mirrors dbt model logic, Spark transformations, and Polars expressions.

🗂️

Multi-Index / Hierarchical Phase 8

When you groupby two or more columns, the result has a multi-level index (dept + city, for example). You can either reset_index() to flatten it, or keep it and access levels with unstack().
# group by two dimensions — multi-index result
result = (
    df.groupby(['dept', 'city'])['salary']
      .mean()
      .reset_index()
      .rename(columns={'salary': 'avg_salary'})
)

# keep multi-index and access a level
grp = df.groupby(['dept','city'])['salary'].mean()
grp.loc[('IT', 'NYC')]

# pivot inner index into columns
grp.unstack()   # city becomes column headers

What is a Window Function? Phase 9

A window function computes a value for each row using a window of surrounding rows — without collapsing the DataFrame like groupby().agg() does. Each row keeps its original position but gains a new computed column based on its group, order, or neighbours. Directly maps to SQL window functions (OVER (PARTITION BY … ORDER BY …)).
Pandas functionSQL equivalentWhat it does
.rank()RANK() / DENSE_RANK() / ROW_NUMBER()Assign a position number within a group
.cumsum()SUM() OVER (ORDER BY …)Running total from first row to current row
.shift(1)LAG(col, 1)Previous row's value
.shift(-1)LEAD(col, 1)Next row's value
.rolling(N)AVG() OVER (ROWS BETWEEN N-1 PRECEDING…)Fixed-size sliding window
.expanding()SUM/AVG() OVER (ROWS UNBOUNDED PRECEDING)Grows from first row to current
.cummax() / .cummin()MAX() OVER (ORDER BY …)Running maximum/minimum
.pct_change()(curr - prev) / prevPeriod-over-period % change
🔢

Row Number Phase 9

Assigns a unique sequential integer to each row within a partition, ordered by a column. Equivalent to SQL's ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC). No ties — every row gets a distinct number.
# ROW_NUMBER within each department
df['row_num'] = (
    df.sort_values(['dept', 'salary'], ascending=[True, False])
      .groupby('dept')
      .cumcount() + 1  # cumcount starts at 0
)

# Alternative: rank with method='first' (no ties)
df['row_num'] = (
    df.groupby('dept')['salary']
      .rank(method='first', ascending=False)
      .astype('int')
)

# keep only top-1 per department
top1 = df[df['row_num'] == 1]

Classic use case: deduplicate — keep the latest record per customer_id.

🏆

rank() — 4 Methods Phase 9

rank() assigns a position within a group. The method argument controls what happens when two rows have the same value (a tie). Choosing the right method changes the output significantly.
average
Ties get avg of their positions. 1,2,2→1,2.5,2.5
min
Ties get lowest rank. 1,2,2→1,2,2 (SQL RANK)
dense
No gaps after ties. 1,2,2→1,2,2 then next=3
first
First occurrence wins. No ties. = ROW_NUMBER
# dense rank within dept (most common for analytics)
df['rank'] = (
    df.groupby('dept')['salary']
      .rank(method='dense', ascending=False)
)

# PERCENTILE rank (0.0 to 1.0)
df['pct_rank'] = (
    df.groupby('dept')['salary']
      .rank(pct=True)
)
⏮️

LAG & LEAD — shift() Phase 9

shift(n) moves column values down by n rows (LAG) or up by n rows (LEAD). Perfect for comparing a current value against the previous/next period. NaN appears where there is no previous/next row.
# LAG — previous row's value
df['prev_sales']  = df['sales'].shift(1)

# LEAD — next row's value
df['next_sales']  = df['sales'].shift(-1)

# month-over-month change
df['mom_change'] = df['sales'] - df['sales'].shift(1)

# % change from previous period
df['mom_pct'] = df['sales'].pct_change() * 100

# LAG within a group (per dept)
df['prev_in_dept'] = (
    df.sort_values('date')
      .groupby('dept')['sales']
      .shift(1)
)
📈

Cumulative Functions Phase 9

Cumulative functions grow the window from the first row up to the current row. cumsum() is a running total. cummax() tracks the highest value seen so far. cumprod() is a running product (used in finance).
# running total of sales
df['running_total'] = df['sales'].cumsum()

# running total per group
df['dept_running_total'] = (
    df.groupby('dept')['sales'].cumsum()
)

# running maximum (all-time high)
df['ath_price'] = df['price'].cummax()

# running minimum (all-time low)
df['atl_price'] = df['price'].cummin()

# cumulative % of total
df['cum_pct'] = (
    df['sales'].cumsum() / df['sales'].sum() * 100
)
🎡

Rolling Window Phase 9

rolling(N) applies a function over a fixed-size sliding window of N rows. The window slides one row at a time. Used for smoothing noisy data, trend detection, and anomaly detection. First N-1 rows produce NaN.
# 7-day rolling average (smoothing)
df['7d_avg'] = df['sales'].rolling(7).mean()

# avoid NaN at start with min_periods
df['7d_avg'] = df['sales'].rolling(7, min_periods=1).mean()

# rolling std dev (volatility / anomaly detection)
df['volatility'] = df['price'].rolling(30).std()

# rolling max (e.g. peak load in last 24h)
df['peak_24h'] = df['load'].rolling(24).max()

# expanding = grow from start (no fixed size)
df['cumulative_avg'] = df['sales'].expanding().mean()
🌍

Window Function — Famous Real-World Examples Phase 9

These are the patterns you'll see in actual data engineering and analytics roles — e-commerce, SaaS, finance, and platform analytics.

ROW_NUMBER Deduplicate — keep latest record

Keep only the most recent record per customer. Used in data lakes to remove duplicate ingestions.
# sort descending by date, row_number per customer
df['rn'] = (
    df.sort_values('updated_at', ascending=False)
      .groupby('customer_id')
      .cumcount() + 1
)
latest = df[df['rn'] == 1]

E-COMMERCE Running Revenue per Product

Track cumulative revenue over time per product line. Common in sales dashboards (Shopify, Amazon analytics).
df = df.sort_values(['product', 'date'])

df['cum_revenue'] = (
    df.groupby('product')['revenue']
      .cumsum()
)

DENSE_RANK Top-N per Category

Find top 3 best-selling products per category. Used in recommendation engines and merchandising reports.
df['rank'] = (
    df.groupby('category')['units_sold']
      .rank(method='dense', ascending=False)
)
top3 = df[df['rank'] <= 3]

SAAS Month-over-Month Growth

Compare current month's MRR against prior month. Standard metric for SaaS dashboards (Stripe, Chargebee).
df = df.sort_values('month')

df['prev_mrr']  = df['mrr'].shift(1)
df['mom_growth'] = (
    (df['mrr'] - df['prev_mrr'])
    / df['prev_mrr'] * 100
).round(2)

FINANCE 20-day Moving Average (stock)

Classic technical indicator — smooth out daily noise to reveal trend direction. Used in quant finance and trading systems.
df = df.sort_values('date')

df['ma20'] = (
    df['close_price']
      .rolling(20, min_periods=1)
      .mean()
)

MONITORING Anomaly Detection

Flag rows where a metric is more than 2 standard deviations from the 30-period rolling mean. Used in ops monitoring (Datadog-style alerting).
mu  = df['latency'].rolling(30).mean()
sig = df['latency'].rolling(30).std()

df['anomaly'] = (
    df['latency'] > mu + 2 * sig
)

RETAIL % of Category Total

What fraction of the category's total sales does each product contribute? Classic "contribution %" metric in retail analytics.
df['cat_total'] = (
    df.groupby('category')['sales']
      .transform('sum')
)
df['pct_of_cat'] = (
    df['sales'] / df['cat_total'] * 100
).round(1)

HR / PEOPLE Salary Percentile within Dept

Rank each employee as a percentile within their department — useful for compensation benchmarking and equity analysis.
df['sal_percentile'] = (
    df.groupby('dept')['salary']
      .rank(pct=True)
      * 100
).round(1)
# 95.0 = top 5% in their dept

Datetime Operations

📅

Datetime Operations Phase 10

Pandas stores dates as datetime64 objects. The .dt accessor extracts parts (year, month, weekday…) — similar to the str accessor for strings. resample() groups a time-indexed DataFrame by time periods.
# parse strings to datetime
df['date'] = pd.to_datetime(df['date_str'])

# extract components via .dt accessor
df['year']    = df['date'].dt.year
df['month']   = df['date'].dt.month
df['day']     = df['date'].dt.day
df['weekday'] = df['date'].dt.day_name()   # 'Monday'
df['quarter'] = df['date'].dt.quarter

# resample to monthly sum
df.set_index('date').resample('ME').sum()

# filter a date range
df[df['date'].between('2024-01-01', '2024-06-30')]

# days between two dates
df['tenure_days'] = (pd.Timestamp.today() - df['hire_date']).dt.days

Performance & Scale

📦

Reading Large Files Phase 12

usecols avoids loading columns you don't need. dtype pre-specifies types so Pandas doesn't guess (guessing wastes memory). chunksize reads the file in batches — critical for files that won't fit in RAM.
# selective load — only needed columns + types
df = pd.read_csv('big.csv',
    usecols = ['id', 'salary', 'dept'],
    dtype   = {'id': 'int32', 'salary': 'float32'},
    nrows   = 100_000   # sample for exploration
)

# chunk processing — memory-safe ETL loop
results = []
for chunk in pd.read_csv('huge.csv', chunksize=10_000):
    processed = process(chunk)
    results.append(processed)

final = pd.concat(results, ignore_index=True)

Chunk processing = streaming mindset → direct bridge to Spark's partition model.

🧮

Memory Optimisation Phase 14

Downcasting uses smaller integer/float types (int32 instead of int64, float32 instead of float64) to cut memory in half. category dtype is extremely efficient for columns with few unique values (like dept, status, country).
# inspect current memory usage
df.info(memory_usage='deep')

# downcast: int64 → int32 (saves 50%)
df['id']     = df['id'].astype('int32')
df['salary'] = df['salary'].astype('float32')

# category dtype for low-cardinality strings
df['dept']   = df['dept'].astype('category')
df['status'] = df['status'].astype('category')

# drop unneeded columns immediately
df.drop(columns=['_tmp', 'junk_col'], inplace=True)
🚀

Vectorisation — no Python loops Phase 15

Vectorised operations work on the entire column at once using compiled C code under the hood — no Python interpreter per row. This is 10–100× faster than looping. Think of it as operating on the whole array in one shot.
❌ Slow — Python for loop
for i in range(len(df)):
    df.at[i, 'bonus'] = df.at[i, 'salary'] * 0.1
✅ Fast — vectorised arithmetic
df['bonus'] = df['salary'] * 0.1
✅ Conditional — np.where instead of apply
import numpy as np

# 2-way condition
df['level'] = np.where(df['salary'] > 90000, 'Senior', 'Junior')

# multi-way — np.select
conditions = [
    df['salary'] > 100000,
    df['salary'] > 80000,
]
choices = ['L5', 'L4']
df['level'] = np.select(conditions, choices, default='L3')

Exporting & Quick Reference

💾

Exporting Outputs Phase 16

to_parquet() is the preferred format in Data Engineering — columnar, compressed, and schema-preserving. Use to_csv() for human-readable exchange. Always set index=False unless you explicitly want the index as a column.
# CSV — readable, no compression
df.to_csv('output.csv', index=False)

# Parquet — preferred for DE (Delta Lake, S3, Databricks)
df.to_parquet('output.parquet', index=False)

# JSON (records = one object per row)
df.to_json('output.json', orient='records', indent=2)

# Excel
df.to_excel('output.xlsx', index=False, sheet_name='Data')
